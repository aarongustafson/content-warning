<content-warning>

A web component for block and inline content warnings. See the README for installation and API documentation.

Most examples author hidden so warning content stays hidden before upgrade and without JavaScript. The inline examples retain visible native text instead. Once loaded, the component adds a native reveal button. Reader Mode tools may still extract content; this isn’t an access-control mechanism.

Block Content Warning

A block-level content warning that overlays the entire content area.

Single Warning Type

Wrap the content and set type to name the warning. Tab to its button, then press Enter or Space to reveal it. Without JavaScript, authored hidden keeps this content hidden. 

<content-warning type="violence" hidden>
  <p>This content contains graphic violence.</p>
  <p>The scene describes a battle and its aftermath.</p>
</content-warning>

This content contains graphic violence.

The scene describes a battle and its aftermath.

Multiple Warning Types

Use space-separated types for multiple warning categories. 

<content-warning type="violence spoilers nsfw" hidden>
  <p>Contains violence, spoilers, and mature content.</p>
  <p>The protagonist dies in the final battle, sacrificing themselves to save their friends.</p>
</content-warning>

Contains violence, spoilers, and mature content.

The protagonist dies in the final battle, sacrificing themselves to save their friends.

Inline Content Warning

An inline content warning that works within text flow.

Inline Usage

Add inline to place the button within a sentence. This example omits hidden, so “episode 5” remains visible without JavaScript. Add hidden if that fallback would expose content you need to conceal. 

<p>
  The character dies in
  <content-warning type="spoilers" inline>
    episode 5
  </content-warning>.
</p>

The character dies in episode 5.

Multiple Inline Warnings

You can have multiple inline warnings in one sentence. 

<p>
  <content-warning type="spoilers" inline>Jon</content-warning>
  meets <content-warning type="spoilers" inline>Daenerys</content-warning>
  in season 7.
</p>

Jon meets Daenerys in season 7.

Content Hiding Modes

The component offers two modes for hiding content, each with different trade-offs.

Default Mode (Dark Overlay)

After render, the component applies hidden and inert to its content wrapper. inert prevents interaction and excludes the content from the accessibility tree. Block content keeps its layout beneath a dark, translucent overlay because the wrapper’s CSS overrides native hidden display. Authored hidden hides the whole element before upgrade; Reader Mode behavior still varies across tools. 

<content-warning type="sensitive content" hidden>
  <p>The overlay covers this content until you reveal it.</p>
</content-warning>

The overlay covers this content until you reveal it.

Blur Mode (Visual Only)

Content is visually obscured with CSS blur but remains in the DOM. The wrapper uses aria-hidden="true" to exclude it from the accessibility tree, not inert. Avoid focusable descendants in blur examples. Bare text nodes aren’t blurred; inline warnings hide their wrapper instead. Not guaranteed to be hidden from Reader Mode. 

<content-warning type="spoilers" blur hidden>
  <p>This content is blurred visually and may be extracted by Reader Mode.</p>
</content-warning>

This content is blurred visually and may be extracted by Reader Mode.

Custom Blur Amount

Adjust the blur intensity using the --content-warning-blur-amount CSS custom property. 

<style>
  .light-blur {
    --content-warning-blur-amount: 5px;
  }
  .heavy-blur {
    --content-warning-blur-amount: 20px;
  }
</style>

<content-warning type="spoilers" blur class="light-blur" hidden>
  <p>Lightly blurred content (5px blur)</p>
  <p>Text is more readable through the blur.</p>
</content-warning>

<br><br>
<content-warning type="spoilers" blur class="heavy-blur" hidden>
  <p>Heavily blurred content (20px blur)</p>
  <p>Text is much harder to read through the blur.</p>
</content-warning>

Custom Styling

Customize the appearance using CSS Shadow Parts.

Custom Colors

Set both button colors to keep the label on an opaque backplate. The overlay can have a separate background; keep the focus outline visible. 

<style>
  .custom-warning::part(overlay) {
    background: rgba(139, 0, 0, 0.95);
  }
  .custom-warning::part(button) {
    color: #fff;
    border: 3px solid #ff6b6b;
    padding: 2rem;
    background: #260000;
    border-radius: 0.5rem;
  }
</style>

<content-warning type="horror" class="custom-warning" hidden>
  <p>This is scary content with custom styling!</p>
  <p>The dark red background and red border make it stand out.</p>
</content-warning>

This is scary content with custom styling!

The dark red background and red border make it stand out.

Styled Button Text

Style the button text and appearance.

<style>
  .styled-parts::part(button) {
    text-transform: uppercase;
    letter-spacing: 0.15em;
    font-weight: 900;
    background: #333;
    color: #fff;
    border-radius: 0.5rem;
  }
</style>

<content-warning type="mature" class="styled-parts" hidden>
  <p>This content is for mature audiences.</p>
</content-warning>

This content is for mature audiences.

Event Handling

Listen for the revealed event to track user interactions.

Tracking Reveals

Activate the warning to update the status below it. The event fires once per reveal and supplies the authored type. 

<content-warning type="spoilers" id="tracked" hidden>
  <p>This is the secret content that was revealed!</p>
</content-warning>
<p id="status">Status: Hidden</p>

<script>
  document.getElementById('tracked')
    .addEventListener('content-warning:revealed', (e) => {
      document.getElementById('status').textContent =
        `Status: Revealed (${e.detail.type})`;
    });
</script>

This is the secret content that was revealed!

Status: Hidden

Labels and Translations

Customize the button label using label-prefix and label-suffix attributes for your application’s vocabulary or a different language. Translate type too, and set lang on translated content. See the label reference for punctuation and defaults.

Use Your Application’s Vocabulary

Change the prefix and suffix to fit a review workflow. These attributes change the label, not the reveal behavior. 

<content-warning
  type="plot details"
  label-prefix="Review note"
  label-suffix="Show details"
  hidden>
  <p>The review discusses the ending.</p>
</content-warning>

The review discusses the ending.

French Translation

Use lang="fr" for French. Each label part can also be styled, while the button keeps an opaque background. 

<style>
  .french-warning::part(button) {
    background: #111;
    color: #fff;
  }
  .french-warning::part(label-prefix) {
    font-weight: bold;
    color: #ffeb3b;
  }
  .french-warning::part(label-suffix) {
    font-size: 0.875em;
  }
</style>

<content-warning
  type="contenu sensible"
  label-prefix="Avertissement"
  label-suffix="Cliquez pour révéler"
  class="french-warning"
  lang="fr"
  hidden
>
  <p>Ce contenu pourrait être considéré comme sensible par certains utilisateurs. Veuillez faire preuve de discrétion.</p>
</content-warning>

Ce contenu pourrait être considéré comme sensible par certains utilisateurs. Veuillez faire preuve de discrétion.

No Suffix

Set label-suffix="false" to hide the suffix entirely. 

<content-warning
  type="graphic content"
  label-suffix="false"
  hidden
>
  <p>This warning has no suffix text—just the prefix and type.</p>
</content-warning>

This warning has no suffix text—just the prefix and type.
